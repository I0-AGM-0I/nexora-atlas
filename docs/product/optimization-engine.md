# Optimization & Waste Detection Specification - NEXORA ATLAS

## 1. Principles of Explainable Waste Detection
Every optimization finding generated by ATLAS must be deterministic, auditable, and substantiated by empirical evidence. ATLAS rejects "black-box" recommendations.

## 2. Waste Detection Rule Categories
1. **Low-Utilization Compute**:
   - Condition: EC2 instances where 95th percentile CPU < 10% and Memory < 15% over 14+ observed days.
   - Evidence: Daily p95 CPU and memory curves.
2. **Oversized Instances**:
   - Condition: Instance family provisioned with excessive vCPU/RAM relative to sustained peak demand.
   - Recommended Action: Downsize to matching family (e.g., `m5.4xlarge` → `m5.large`).
3. **Unattached Storage**:
   - Condition: EBS volumes in `available` (detached) state for > 7 days.
   - Recommended Action: Snapshot and terminate.
4. **Orphaned Snapshots**:
   - Condition: Automated snapshot retention exceeding compliance policy without active volume lineage.
5. **Idle Database Clusters**:
   - Condition: RDS instances with zero connections during 90% of business hours.
6. **Non-Production Working Hours**:
   - Condition: Development and staging environments running 24/7 rather than auto-stopping outside 09:00–18:00 local time.

## 3. Recommendation Data Contract
Every recommendation must produce:
- Resource Identifier & ARN
- Current Configuration vs. Proposed Configuration
- Estimated Monthly Savings (₹) & Estimated Annual Savings (₹)
- Risk Classification (`LOW`, `MEDIUM`, `HIGH`)
- Confidence Percentage (e.g. 94%)
- Empirical Evidence & Stated Assumptions
